# 拾页：剪藏操作调整（复制链接已移除）

> 右上角复制链接功能已在 0.6.2 移除；以下复制实现仅作历史记录。

日期：2026-10-10 · 版本：0.4.4

用户任务：复制当前采集文章的完整原文链接、只保留必要标题信息、最多三个标签、在标题与剪藏方式之间直接剪藏。沿用既定暖白纸面、绿色控件、340px 全高右侧面板、12px 外边距和统一字体，不另开设计方向。

## 操作与状态

- 右上角「复制链接」取当前 `pageData.url`，完整保留查询参数、锚点和编码内容。成功短暂显示勾号与「已复制」；失败显示「重试复制」，并以屏幕阅读器状态解释失败。读取未完成时禁用；登录与成功页隐藏。
- 标题下方不再显示网址。来源、标题编辑、完整原文 URL 和正文中的来源信息仍参与保存。
- 「剪藏」按钮位于标题与六项方式之间。中间表单滚动时按钮停留在内容区顶部，分类和标签可继续编辑；底部只保留草稿提示与退出。Command / Ctrl + Enter 仍可提交，提交中显示「正在剪藏…」。
- 标签计数改为 `0 / 3`，单个仍最多 40 字。成签、批量文本、已有标签、未确认输入与后台提交均限制三项；满额隐藏建议。被拒绝的输入保留，错误自动滚动至可见位置。已有草稿超限时保留全部标签，提示删减，避免丢失输入。

复制首先使用浏览器 Clipboard API，失败尝试选区复制，临时字段随后清理并恢复焦点。生产 iframe 委派 `clipboard-write`，未新增 Chrome 扩展权限。参考 [MDN Clipboard API](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard_API) 的 iframe 策略说明。PageHush API、数据库和 schema 不变，三项是扩展自己的产品限制。

## 验证

扩展集成检查在隔离 Chromium 中运行：真实 worker、采集、存储、表单与 HTTP 流程；本地模拟 API 每轮创建 9 个草稿。剪贴板写入和截图 API 只模拟平台边界，未读取或改写用户系统剪贴板；完整含查询参数和锚点的原文 URL、原生写入失败/回退失败/回退成功、临时字段清理与焦点均有断言。

额外覆盖：主操作位置与滚动可见、登录隐藏复制、三项计数/满额建议、第四项拒绝、批量文本与待确认输入提交拦截、旧草稿四项保留/删减、worker 上限验证，以及原登录/分类/六种剪藏/失败重试/关闭恢复流程。

最终连续三次检查结果和独立画面评审见下方记录。未部署或自动重新加载用户扩展；使用时在 Chrome 扩展管理页重新加载拾页，刷新原网页后打开。

连续三次最终检查均通过，记录为 `evidence/clip-actions-check-1.log`、`clip-actions-check-2.log`、`clip-actions-check-3.log`，每次 9 个隔离模拟草稿。

独立存量画面评审未发现必须修改的静态视觉偏离或可直接删除的无用文案。首次交付的动效录制只显示恢复成功页，评审要求补四段；后续以阶段图和报告确认证据闭合。随后复核发现滚动后方式选中底色丢失，已隔离列表绘制层并重取窄屏图，保证选中底板与勾号对齐。最终独立复核确认已修正，没有剩余必须修改的问题、动效证据缺口或应删除的无用文字。
