## 项目与参考

当前项目是无构建 Chrome MV3 扩展：popup 负责界面，background 负责网络请求，content script 负责网页采集。PageHush 使用访问码换取 token，分类对象是 topics，保存对象为文章草稿。

已阅读当前全部实现和计划，核对 PageHush 认证、topics、文章创建与 schema；阅读 clipper01 manifest 和登录、剪藏状态、笔记本选择相关打包片段。参考其「登录 → 剪藏对象与类型 → 保存位置 → 保存结果」结构，使用 PageHush topics 替代 notebook。未修改参考扩展，未搬运官方 bundle 或素材。

## 选定方向

用户来弹窗是为了快速留住当前网页。登录页以访问码为唯一主要输入；工作台以当前文章、分类、保存为主线。暖白纸面对应阅读与收集，深绿色控件呼应页息知识库。剪藏工具命名为「拾页 PageHush Clipper」，主产品为「页息 PageHush」，口号为「拾起灵感，留住好文章。」；使用用户提供的 `clipper-logo.png`，导出 16/32/48/128 图标并用于工具栏、页头和登录页。

流程先收敛到单一工作台，不引入新路由或框架。登录、工作台、成功和设置互斥；API 配置从首次使用流程中移到设置。默认线上地址内置；保留自托管实例设置。

常用路径由「配置/登录/类型与分类/保存」收敛到「首次输入访问码/确认分类与类型/保存」，后续保持登录时直接进入剪藏。没有计入未做过的人工任务统计，不虚构步数改善。

## 关键实现

- 默认服务：`https://pagehush.yohoia.cn`；同域 `/v1` 接口。
- background 统一发起登录、session、topics、logout、create 请求，不携带网页 Cookie；token 绑定 API 地址，切换服务先撤销旧会话。
- remember 决定 local 或 session 存储，访问码只用于当前登录请求。
- 六格数字访问码输入，支持逐位跳转、整码粘贴、退格返回、方向键移动及显示/隐藏；六位填满后启用登录。错误访问码清空并回到首格，网络故障保留输入。
- 根文档固定 400×600，移除视口宽度上限引起的 Chrome 弹窗自适应收缩；页头固定，内容区域独立滚动。
- 无登录时不抓正文；已登录时显示当前网页采集预览，保存提交这份预览对应的内容。
- topics 失败可重试，401 重登，网络问题保留凭证。分类为空时保存创建「学习」。
- `topicName` 仅在需要分类名时发送，避免发送 schema 不允许的 null。
- Markdown 文本预览使用 `textContent`；网页内容不作为可执行 HTML 插入弹窗。
- draft 输入按标签页及其原 URL 隔离，存在 session 存储；保存结果只持久化 ID、slug、标题和分类摘要。
- 后台保存与 popup 生命周期分开，阻止并发重复请求，关闭弹窗后恢复结果；超时/中断不自动重发。
- 保存响应持久化 `shortId`，打开页息优先 `/a/:shortId`；旧 API 与旧保存记录回退 `/articles/:id`。API 的短标识由完整 UUID 编码而来，文章标题与浏览器地址分离。
- 标题、来源、图片、列表、代码、表格保持，正文超过 500,000 字符明确提示改用选区。

## 验证与边界

`tests/check.mjs` 在临时 Chromium 配置中实际加载扩展，使用隔离 HTTP API，验证真实 background、Chrome storage、content script、消息、请求和 popup 状态。仅把「测试 tab 打开的 popup 页」的活动页查询指向测试原网页，补偿它与工具栏 popup 的入口差异。

覆盖：语法/manifest、线上默认与旧配置迁移、非法 URL 拒绝、登录前互斥/不联网、错误码/正确码、记住与会话登录、topics、代码和嵌套列表、危险内容清理、标题/标签、保存失败/输入重开恢复、保存后读回/打开 URL、选区与书签、空分类、topics 重试、关闭弹窗继续保存、并发去重、token 过期、服务切换撤销凭证。连续三轮结果：第 1 轮通过，第 2 轮通过，第 3 轮通过；每轮验证 6 次隔离草稿保存，不向生产服务写入。记录见 `evidence/check-1.log`、`check-2.log`、`check-3.log`。

0.2.1 追加验证通过：六格输入自动跳转、退格与方向键、过滤非数字、从任意格粘贴完整访问码、错误码清空并重新聚焦、显示/隐藏、原始 Logo 加载；初始视口宽度 80/400/1280 下文档均保持 400×600，展开内容只滚动正文，默认保存按钮可见。记录见 `evidence/shiye-check-1.log`。已在用户当前 Chrome 重新加载「拾页」0.2.1 并检查真实工具栏弹窗，确认尺寸正常与六格界面可见。最终四状态截图见 `evidence/shiye/`，没有控制台错误、横向溢出或加载失败图片。
